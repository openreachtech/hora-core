# Hora Kit

Hora のコア — AI エージェントツールが読み込むスキルとエージェント — を、構築を行うリポジトリへ運ぶコンテナです。

同梱物はすべて単一のディレクトリ `kit/` 配下にあり、エージェントツールが期待する配置をそのまま写しています。

```
kit/
├── agents/   サブエージェント定義
└── skills/   スキル定義
```

`kit/` は特定のツール名ではなく、中身が何であるかに基づいて命名しています。そのため同じペイロードを、リポジトリが使うどのエージェントツールへも配置できます。本書がドキュメント化している対象は Claude Code で、その設定ディレクトリは `.claude/` です。

npm が公開するのは `dist/` で、パックのたびに `kit/` から生成されます。両者の内容は同一なので、上の配置はそのままインストール後のパッケージの配置でもあります。

これに加えて、本パッケージは実行ファイルを 1 つ同梱しています。その役目は、上記のペイロードをリポジトリへ配置することだけです。インポートするものはありません。

Hora 自体の仕組み — このキットが運ぶ手法 — はボイラープレート側に記述しています: [openreachtech/hora-boilerplate](https://github.com/openreachtech/hora-boilerplate)

## インストール

Node.js 20.0.0 以降が必要です（`package.json` の `engines` が宣言している下限）。CI は現行の LTS でビルドしています。

```sh
npm install -D @openreachtech/hora
```

本パッケージ自身はインストールスクリプトを同梱していません。したがって依存に追加しても、パッケージが入るだけで、何も配置されません。プロジェクト自身の `postinstall` としてコマンドを宣言してください。それだけで、`npm install` がリポジトリをキットで武装させます。

```json
{
  "scripts": {
    "postinstall": "hora-core install"
  }
}
```

プロジェクト自身のスクリプトは、npm が v12 以降で差し止める対象の外にあります。したがって、そのプロジェクトをクローンする人に何も要求しません。ここで `npx` は不要です。ライフサイクルスクリプトは `node_modules/.bin` を PATH に入れて実行されるためです。

いま宣言したフックが効くのは、次の `npm install` からです。最初の配置は、コマンドを自分で実行してください。一度だけ配置したい場合や、フックを置けないリポジトリでも同じです。

```sh
npx --no hora-core install
```

## 使い方

キットはリポジトリの `.claude/` — エージェントツールが読み込むディレクトリ — へ配置されます。`dist/agents/` は `.claude/agents/` へ、`dist/skills/` は `.claude/skills/` へ。スキル探索が見るのはこのパスだけで、パッケージ自身のディレクトリは対象外です。つまり、このクローンがキットを可視化する唯一の手段です。以降、スキルは `/hora`、`/hora-plan`、`/hora-build` のようにスラッシュコマンドとして呼び出せます。

`dist/` の各ディレクトリは同名のディレクトリへ運ばれ、そこに既にあるものはそのまま残ります。リポジトリが自作したスキルは、その名前が本パッケージの配布物と一致しない限り、インストール済みのものと並んで無傷で残ります。

### リンクではなくディレクトリ

`.claude/` と、その中の payload ディレクトリは、シンボリックリンクではなくリポジトリのディレクトリである必要があります。インストールは対象へ至る各段を検査し、いずれかがリンクであれば、何も書き込まず、何も削除せずに終了します。 インストール内容の記録である `.hora/equip-core.json` も同じように検査します。ここにリンクがあると、書き込みがリンク先へ届き、その中身を上書きしてしまうためです。

何も運ばなかったインストールは、その理由を告げ、0 以外の終了コードで終わります。プロジェクト自身の `postinstall` として実行しているなら、それは `npm install` の出力に現れます。単独で実行した場合は `npx --no hora-core install` が同じことを告げます。

リンクはコマンドを実行する人の指示ではなく、リポジトリの中身です。それを辿ると、エントリをどこへ書くか、そして前回のエントリをどこから消すかを、リポジトリ側が決められることになります。

`.claude/` 全体をリポジトリ間で共有するディレクトリへ向けている場合は、そのディレクトリを直接名指ししてください。`npx --no hora-core install --dir <解決先のディレクトリ>` で同じ状態に到達し、リンクがある以上、キットは `.claude/` から見えます。payload ディレクトリだけをリンクにしている場合、そこへインストールする方法はありません。`--dir` が指すのは payload を収めるディレクトリであって、payload そのものではないためです。実ディレクトリに置き換えてください。

### インストール内容を最新に保つ

配置されたキットはリポジトリのソースではなく本パッケージのビルド成果物です。無視した上で、自分のものを名指しで戻してください。

```gitignore
.claude/agents/*
.claude/skills/*
!.claude/skills/my-own-skill/
.hora/
```

名前の接頭辞ではなくディレクトリ全体で指定するのは意図的です。本パッケージの配布物はリリースごとに変わるため、今日の名前に合わせて書いたパターンは、何も告げずに古くなります。

引数なしの `npm install` はプロジェクトの `postinstall` を再実行するので、キットも追従します。パッケージをコマンドラインで名指しする更新（`npm install @openreachtech/hora@latest`）では走りません。フックを置いていないリポジトリも同じです。その場合は、同じコマンドを再実行してください。

```sh
npx --no hora-core install
```

`install` は繰り返し実行できます。前回のインストール内容 — `.hora/equip-core.json` に記録されています — と、本パッケージが配布するエントリと同名のものを削除してから、現在のキットをコピーします。したがって、リネームされたスキルや削除されたスキルが残ることはありません。`dist/` を手でコピーしていたリポジトリも、初回の実行で整理されます。

### コマンド

| コマンド | 動作 |
| :-- | :-- |
| `hora-core install` | キットをインストールし、前回インストールしたものを置き換える |
| `hora-core list` | インストール対象のエントリを表示する。インストールは行わない |
| `hora-core uninstall` | 本パッケージがインストールしたエントリとマニフェストを削除する |
| `hora-core help` | 使い方を表示する |

`--dir <path>` を指定すると `.claude` 以外のディレクトリへインストールします。
